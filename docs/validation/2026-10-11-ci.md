The [toolchain decision](../adr/002-native-ci-toolchains.md) records primary
sources and the macOS profile's limits. CI is development CPU coverage, not a
release-vcpkg build. Linux/macOS also provision FFmpeg for the existing real
decode integration test. The Windows integration suite retains its explicit
dependency/symlink skips when those capabilities are absent.

The required probe now links the same Threads target as application code,
checks jthread's feature macro explicitly and reports the selected compiler and
missing library requirements. It still compiles actual API uses. No required
feature, C++ standard, warning level or milestone threshold was lowered.

Code inspection also identified Windows build hazards after configuration:
Windows SDK min/max macros and MSVC's deprecated `fopen` diagnostic under `/WX`.
Private target definitions prevent the macros, and atomic bundle writes use
`_wfopen_s` on Windows while preserving native filesystem paths through staging
and replacement. The existing public bundle round-trip test now runs both ASCII
and non-ASCII directory names with spaces, including corrupt assets and invalid
paths. Existing failed-publication preservation checks remain enabled.
